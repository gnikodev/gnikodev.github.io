В эпоху бурного развития технологий расстраиваешься, когда у тебя нет возможности получить доступ к новым программам или сервисам, которые так сильно хотелось испытать.

Так и в случае с ChatGPT. Для определённых стран, сетей и IP-адресов доступ к сервису может быть ограничен. Конечно, есть куча способов обхода с использованием сторонних туннелей, или же можно поднять свой. Но и с ними доступ не гарантирован: адрес выхода тоже может попасть под ограничения.

Но есть ещё один способ, который тоже может помочь решить проблему: использование DNS-сервиса с проксированием отдельных доменов. Например, такой доступ предлагает [Comss.one DNS](https://www.comss.ru/page.php?id=7315). В этой схеме DNS возвращает адрес посредника вместо адреса самого сервиса. Это не свойство любого альтернативного DNS: обычная смена резолвера не меняет ваш внешний IP. Помимо этого, оператор заявляет блокировку рекламы на других сайтах — примерно так же, как при использовании DNS-серверов AdGuard.

Этот способ, конечно, не даёт стопроцентной гарантии. Перечень поддерживаемых сервисов и параметры подключения берите на сайте оператора: они меняются.

Настроить взаимодействие устройства с новыми серверами можно несколькими способами. Перед изменениями сохраните текущие параметры, чтобы при проблемах вернуть их или включить автоматическое получение DNS.

## Настройка DNS-серверов для всей сети (например, на роутере)

Для этого нужно получить доступ к панели управления роутера. Обычно достучаться до неё можно через адреса 192.168.0.1 или 192.168.1.1. Либо можно посмотреть на обратную сторону своего устройства: чаще всего там написаны и адрес, и логин с паролем для доступа в панель администратора.

Я не буду описывать все способы смены DNS для всех роутеров — их можно найти в интернете. Оставлю ссылки на инструкции для самых популярных моделей.

- [tp-link](https://www.tp-link.com/ru/support/faq/1712/)
- [d-link](https://www.dlink.ru/by/faq/391/1037.html)
- [keenetic](https://help.keenetic.com/hc/ru/articles/213966649-%D0%98%D1%81%D0%BF%D0%BE%D0%BB%D1%8C%D0%B7%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5-%D0%BF%D1%83%D0%B1%D0%BB%D0%B8%D1%87%D0%BD%D1%8B%D1%85-DNS-%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%D0%BE%D0%B2)

### Плюсы

- Не нужно настраивать каждое устройство вручную, если оно использует DNS, выданный роутером. Собственный DNS устройства, защищённый DNS в браузере или VPN могут обойти эту настройку.

### Минусы

- Есть вероятность, что некоторые другие сайты будут недоступны.
- Есть вероятность медленного разрешения имён из-за нагрузки на DNS, а при проксировании — и снижения скорости самого соединения.
- Стороннему DNS-оператору приходится доверять: он может видеть запрашиваемые домены, а подмена записей может направить соединение не туда 🧐. Но она сама по себе не позволяет незаметно расшифровать корректно проверяемое HTTPS-соединение. Не игнорируйте ошибки сертификатов и не устанавливайте неизвестные корневые сертификаты ради доступа.

## Получение конкретного адреса

Для запроса к конкретному DNS-серверу нужно взять его актуальный IP из документации оператора и выполнить команду ниже, заменив `DNS_SERVER_IP` этим адресом. Обычный `nslookup` использует DNS на порту 53: адрес DoH или DoT нельзя просто подставить вместо IP в эту команду.

```bash
nslookup chatgpt.com DNS_SERVER_IP
```

Ответ будет примерно такого вида (IP-адреса условные, не для настройки):

```text
Server:         192.0.2.53
Address:        192.0.2.53#53

Non-authoritative answer:
Name:   chatgpt.com
Address: 192.0.2.1
```

В ответе после `Name` перечислены адреса запрошенного домена. Сам по себе вывод `nslookup` не доказывает, что это прокси: обычные CDN тоже возвращают разные IP. Он также не проверяет доступность ChatGPT или безопасность посредника.

Для привязки конкретного домена к IP можно использовать файл `hosts`, если оператор прокси поддерживает такой способ и указывает адрес для этого домена. Как редактировать файл и добавлять связку доменных имён и IP-адресов, описано в статьях ниже. Перед изменениями сохраните копию файла:

- [Настройка файла hosts в Linux](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/rabota-s-dns-serverami/fayl-hosts-na-linux#0)
- [Настройка файла hosts в Windows](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/rabota-s-dns-serverami/fayl-hosts-dlya-windows-10)
- [Настройка файла hosts в macOS](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/rabota-s-dns-serverami/fayl-hosts-na-macos)

Один сервер не обязан обслуживать и `chatgpt.com`, и домены авторизации, поэтому нельзя назначать всем этим доменам адрес из одного ответа DNS. Записи `hosts` влияют только на перечисленные имена в приложениях, которые учитывают этот файл, и не настраивают системный прокси. Если адрес перестанет работать, запись придётся обновить или удалить.
